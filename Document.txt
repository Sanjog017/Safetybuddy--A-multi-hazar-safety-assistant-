# SafetyBuddy - Multi-Hazard Safety Assistant Documentation

## 1. Introduction

SafetyBuddy is a comprehensive terminal-based safety assistant application designed to provide critical information during various natural disasters and emergency situations. This C-based application operates entirely offline, making it accessible even during infrastructure failures or network outages. The project aims to increase disaster preparedness and response effectiveness by providing immediate access to life-saving safety protocols and emergency contact information.

## 2. Objective

The primary objective of SafetyBuddy is to create a reliable, user-friendly tool that delivers:
- Immediate access to critical safety information during emergencies
- Comprehensive guidelines for multiple types of natural disasters
- Emergency contact management for quick access to vital numbers
- First aid instructions for immediate response to injuries
- Educational resources on proper disaster response procedures
- A lightweight application that runs on basic hardware without internet connectivity

## 3. Features

### Current Implementation:
- Interactive menu system with disaster-specific safety instructions
- Support for 5 major disaster types: Earthquakes, Floods, Fires, Landslides, and Storms
- Emergency contact management system (addEmergencyContact function currently empty)
- Display of pre-loaded emergency contacts
- Comprehensive first aid instructions for common emergency situations
- About program information and user guidance

## 4. Modules

Based on current main.c structure:

```c
// Main Modules:
- main(): Main menu and navigation
- Earthquake(): Earthquake safety instructions
- Flood(): Flood safety instructions  
- fire(): Fire safety instructions
- roadAccident(): Road accident safety instructions
- landslide(): Landslide safety instructions
- storm(): Storm/Tornado safety instructions
- emergencyContact(): Display emergency contacts
- addEmergencyContact(): Add emergency contacts (currently empty)
- firstAidInstructions(): First aid guidance
- aboutProgram(): Program information
```

## 6. Data Structures

Current implementation uses:
- Primitive data types: `int` for user choices and menu navigation
- No complex data structures implemented yet
- Future implementation will require:
  - Arrays or structures for emergency contacts storage
  - File I/O operations for persistent data storage
  - Possibly linked lists for dynamic contact management

## 7. Algorithms

Current algorithms:
- Simple switch-case menu system
- Recursive function calls for navigation (causing stack overflow issues)
- Basic input/output operations
- No complex algorithms implemented yet

Future algorithms to implement:
- Input validation algorithms
- File parsing and data storage algorithms
- Search algorithms for emergency contacts
- Quiz mode algorithms for testing knowledge

## 8. File Handling

Current status:

Planned file handling:

## 9. Requirements

### System Requirements:
- Operating System: Linux, Windows, macOS (cross-platform)
- Memory: Minimal (designed for basic hardware)
- Storage: Small footprint (compiled executable only)
- Network: Not required (offline functionality)

### Development Requirements:
- Compiler: GCC (GNU Compiler Collection)
- Standard C libraries: stdio.h, stdlib.h, string.h
- Build system: Basic gcc compilation

### Functional Requirements:
- Display safety instructions for 5 disaster types
- Manage emergency contacts (up to 20)
- Provide first aid instructions
- Support multiple languages (future)
- Quiz functionality (future)
- Configuration management (future)

## 10. Conclusion

SafetyBuddy addresses a critical need for accessible emergency information during natural disasters. The current implementation provides a solid foundation with basic functionality for safety information display. However, significant improvements are needed in areas such as proper navigation, data persistence, input validation, and user experience.

The modular structure of the code allows for easy extension and enhancement according to the phased development plan. Future work will focus on implementing the critical Phase 1 features to make the application fully functional, followed by planned enhancements in Phase 2-4 to create a comprehensive safety assistant tool.

The project successfully demonstrates the potential of simple technology solutions in promoting community resilience and safety during natural disasters while maintaining accessibility for users with limited technological resources.
